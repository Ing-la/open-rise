## 一、生产环境数据库初始化 (P0)

### 问题

打包后的 Electron 应用首次启动会崩溃。`main/db.js` 中生产环境的数据库路径指向 `app.getPath('userData')/openrise.db`——SQLite 自动创建了这个空文件，但没有任何表。而 `prisma` CLI 是 devDependency，打包后不存在，无法执行 `migrate deploy`。

简单说：**开发时靠 `prisma migrate dev` 建表，但用户电脑上没有 Prisma CLI。**

### 方案

**构建时从 schema.prisma 导出完整 DDL，打包进安装包，运行时执行建表。**

```
开发时                        构建时                            运行时
schema.prisma ── migrate diff ──→ schema.sql (所有 CREATE TABLE) ──→ 首次启动执行建表
(唯一设计稿)    --from-empty     (~2KB 纯文本，打包进安装包)
```

### 关键概念

**DDL（Data Definition Language）**：定义数据库结构的 SQL 语句——`CREATE TABLE`、`ALTER TABLE ADD COLUMN`、`CREATE INDEX`。描述"数据库应该长什么样"，不是"怎么操作数据"（那是 DML）。

**`migrate diff --from-empty`**：假设源是空数据库，输出当前 schema 对应的完整建表 SQL。简单、不需要数据库连接、输出确定。缺点是只输出 `CREATE TABLE`，不包含 `ALTER TABLE ADD COLUMN`。

**`db push --dry-run --print`**：连接临时空数据库，比对 schema 后生成完整 DDL。输出的 SQL 同时包含 `CREATE TABLE`（新表）和 `ALTER TABLE ADD COLUMN`（已有表的新列）。运行时 catch 吞掉"已存在"的错误实现幂等。

### 为什么不选更重的方案

| 方案 | 问题 |
|------|------|
| Prisma 引擎打包进 production | 安装包膨胀 ~15MB，需额外配置 `.asar.unpacked` |
| 打包现成的 .db 文件 | 用户有数据后不能换文件；`.db` 已被 `.gitignore` 排除 |
| 运行时 `prisma migrate deploy` | CLI 不在 production 中 |

### 当前决策

**每次发版都当作用户第一次下载软件。** `--from-empty` 只输出 `CREATE TABLE`，没有迁移逻辑。V1 阶段（还没有真实用户）这是最轻量的做法。

当项目**已有真实用户数据**且后续版本需要**给已有表加列**时，改为临时空数据库方案。详见 `docs/project/00-注意事项.md`。

## 二、PrismaClient 单例模式 (P2-3.1)

整个应用只需要一个 PrismaClient 实例，但 `debate.js` 自己 new 了一个：

```js
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();   // 第二根吸管
```

而其他 handler 统一从 `../db` 引入同一个实例——`db.js` 中 `module.exports = prisma`，Node.js 的 `require` 会缓存模块，无论引用多少次都返回同一对象。

**吸管比喻**：数据库连接就像吸管插进奶茶杯。正常是所有人共用一根，`debate.js` 又往同一个杯子单插了一根。SQLite 允许多连接并行读，不会崩，但没必要——改数据库路径时 `db.js` 改了，debate.js 自建实例会漏掉。

**修复**：`const prisma = require('../db');` 即可。

## 三、前端 `any` 类型泛滥 (P2-3.2)

`any` 是告诉 TypeScript"别管这个变量"——放弃类型检查。项目 11 个组件共 62 处 `any`，典型如 `PageShell.tsx`：

```tsx
const [selectedPerson, setSelectedPerson] = useState<any | null>(null);
```

`any` 意味着写错了 TS 也不报错，运行时才暴露：

```tsx
selectedPerson.nonexistent  // TS 闭嘴，运行时 undefined
selectedPerson()            // TS 不吭声，运行时崩溃
```

定义类型后，IDE 直接红线拦截：

```tsx
interface Role { id: string; name: string; soul: string; avatar: string | null; }
const [selectedPerson, setSelectedPerson] = useState<Role | null>(null);
// selectedPerson.nonexistent → ❌ Property does not exist
```

`any[]` 尤其危险——列表渲染时每个元素逃过检查，属性名拼错 = 运行时空白。

**一句话**：`any` 把 TypeScript 降级回 JavaScript。核心数据模型（Brain、Role、Message）值得先定义接口。
