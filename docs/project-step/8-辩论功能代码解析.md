## 1. 前置知识：JS 基础速查

### 变量声明：`const` vs `let`

```javascript
const x = 5;   // 常量，不可重新赋值（类似 Python 的 x = 5 但约定不改）
let y = 10;    // 变量，可重新赋值
// 在 Python 里你直接写 x = 5，没有 const 的概念
```

### 模块导入：`require()` vs Python `import`

```javascript
const fs = require('fs');      // 类似 Python 的 import os
const { app, ipcMain } = require('electron');
// 解构导入，类似 Python 的 from electron import app, ipcMain
```

### 箭头函数：`() => {}` vs Python `lambda`

```javascript
// JS 箭头函数
const add = (a, b) => { return a + b; };
const addShort = (a, b) => a + b;  // 单行可省略 return

// Python 对应
// add = lambda a, b: a + b
```

### 模板字符串：`` `...${}...` `` vs Python f-string

```javascript
const name = 'Alice';
console.log(`Hello ${name}`);  // 类似 Python 的 f"Hello {name}"
```

### 解构赋值 vs Python 解包

```javascript
const obj = { a: 1, b: 2 };
const { a, b } = obj;     // 类似 Python 的 a, b = obj['a'], obj['b']

const arr = [1, 2, 3];
const [x, y, z] = arr;    // 类似 Python 的 x, y, z = arr
```

### 数组方法速查

| JS 写法 | 类似 Python | 说明 |
|---------|-----------|------|
| `arr.map(fn)` | `map(fn, arr)` 或 `[fn(x) for x in arr]` | 每个元素执行 fn，返回新数组 |
| `arr.filter(fn)` | `filter(fn, arr)` 或 `[x for x in arr if fn(x)]` | 保留 fn 返回 true 的元素 |
| `arr.reduce((sum, x) => sum + x, 0)` | `functools.reduce(lambda sum, x: sum + x, arr, 0)` | 累计计算 |
| `arr.forEach(fn)` | `for x in arr: fn(x)` | 遍历执行，不返回值 |
| `arr.slice(0, -N)` | `arr[:-N]` | 负索引截取（和 Python 一模一样！）|
| `arr.find(fn)` | 没有直接等价，需 `next(x for x in arr if fn(x))` | 返回第一个匹配元素 |
| `arr.some(fn)` | `any(fn(x) for x in arr)` | 是否有任意元素满足条件 |
| `arr.join('\n')` | `'\n'.join(arr)` | 注意 Python 是字符串调 join |

### `??` vs `||` vs Python `or`

```javascript
// ?? — 只在「null 或 undefined」时取默认值（最安全）
const x = null ?? 'default';   // → 'default'
const y = 0 ?? 'default';      // → 0（0 不是 null，所以保留 0）
const z = '' ?? 'default';     // → ''（空字符串不是 null，保留）

// || — 「falsy」时取默认值（falsy = false, 0, '', null, undefined）
const a = '' || 'default';     // → 'default'（空字符串是 falsy）
const b = 0 || 'default';      // → 'default'

// Python or 行为类似 ||，不是 ??
// '' or 'default' → 'default'  ❌ 0 or 'default' → 'default'
```

### ⚠️ `??` 不能和 `||` 混用

```javascript
// 错误语法：JS 禁止混合 ?? 和 ||，会报 SyntaxError
// const x = a ?? b || c;

// 正确做法：加括号明确优先级
const x = (a ?? b) || c;  // 先 ?? 再 ||
const y = a ?? (b || c);  // 先 || 再 ??
```

### 可选链：`?.` vs Python `?.` 不存在

```javascript
// data.choices?.[0]?.message?.content
// 如果 data 为 null/undefined，不报错，返回 undefined
// Python 没有这个语法，得写：
// if data and data.get('choices') and data['choices'][0] ...
```

### Spread 操作符：`...arr`

```javascript
const arr1 = [1, 2, 3];
const arr2 = [...arr1, 4, 5];  // → [1, 2, 3, 4, 5]，类似 Python 的 [*arr1, 4, 5]
```

### `Set` — 类似 Python 的 `set`

```javascript
const set = new Set();
set.add('abc');
set.has('abc');  // true
set.delete('abc');
// 类似 Python 的 set()，但没有字面量语法
```

### `try` / `catch` 无参语法

```javascript
// JS 允许 catch 省略参数（Python 不允许）
try {
  JSON.parse(badData);
} catch {
  // 不关心错误类型，直接跳过
}

// Python 必须写 except Exception:
// try:
//   json.loads(bad_data)
// except Exception:
//   pass
```

### Promise.all — 并行执行异步任务

```javascript
// 同时启动多个异步任务，等所有都完成
const results = await Promise.all([
  fetch('/api/a'),
  fetch('/api/b'),
  fetch('/api/c'),
]);
// Python 里是：results = await asyncio.gather(fetch('/api/a'), fetch('/api/b'), fetch('/api/c'))
```

### 数据流概览

```
用户点击「下一步」
    │
    ▼
前端 DebateView.handleStep()
    │ stepDebate(debateId)  ← 通过 IPC 发送
    ▼
后端 debate.js — ipcMain.on('debate:step')
    │
    ├── getNextSpeaker(state)  → 状态机决定下一个谁发言
    │
    └── executeSpeech(event, state, speaker)
          │
          ├── buildSystemPrompt()  → 构造 system prompt
          ├── buildUserMessage()   → 构造 user message
          ├── streamSpeech()       → 调 LLM API（流式）
          │     └── event.sender.send('debate:delta', ...)  ← 逐 token 推送
          │
          └── 存数据库 → event.sender.send('debate:round_done')
                │
                ▼
前端收到 round_done → 更新 UI → 启用「下一步」按钮

--- 所有 5 阶段 16+ 轮发言完成后 ---

后端 getNextSpeaker() 返回 { phase: 'judging' }
    │
    └── executeJudgingPhase1()
          ├── 3 位裁判并行调用 LLM（Promise.all）
          ├── 每人给 8 位辩手打分（4 维度 × 权重）
          ├── 存 DebateScore
          └── 逐裁判推送评分表

用户点击「查看结果」
    │ aggregateDebate(debateId)
    ▼
后端 aggregateJudging()
    ├── 读取所有 DebateScore
    ├── 计算每人的加权平均分
    ├── 算团队总分 → 判定胜负
    ├── 算最佳辩手
    ├── 存 DebateResult
    └── 返回 { winner, bestPro, bestCon, ... }
```

### 辩论流程概览

辩论分 **5 个阶段**，共 **16+ 轮发言**：

```
立论 (opening)      → 正方一辩 + 反方一辩（共 2 轮，固定顺序）
驳论 (rebuttal)     → 反方二辩 + 正方二辩（共 2 轮，固定顺序）
对辩 (cross)        → 双方三辩交替发言（字数上限 300，不固定轮次）
自由辩论 (free)     → 随机选人交替发言（字数上限 800，不固定轮次）
总结 (closing)      → 反方四辩 + 正方四辩（共 2 轮，固定顺序）
裁判评判 (judging)  → 3 位裁判并行评分 → 聚合算分
```

## 3. Prisma 辩论模型详解

文件：`prisma/schema.prisma`

辩论功能使用 **5 个数据模型**：

```
Debate (1)
    ├── DebatePosition (N)   — 辩手/裁判与辩论的关联
    ├── DebateMessage (N)    — 每条发言记录
    ├── DebateScore (N)      — 裁判对每人的评分
    └── DebateResult (1)     — 最终结果
```

### Debate 模型

```prisma
model Debate {
  id          String   @id @default(uuid())
  proTopic    String   // 正方辩题
  conTopic    String   // 反方辩题
  background  String?  // 背景资料
  debugMode   Boolean  @default(false) // 调试模式
  summary         String?  // 辩论结束后由裁判 LLM 输出自动生成的摘要
  judgePersonas   String?  // JSON 数组，如 "[1,3,7]"，记录本场选中的 3 个裁判人格 id
  status          String   @default("ongoing") // "ongoing" | "completed"
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  positions   DebatePosition[]
  messages    DebateMessage[]
  scores      DebateScore[]
  result      DebateResult?
}
```

| 字段 | 类型（JS/Prisma） | 类比 Python/SQLAlchemy | 说明 |
|------|-------------------|----------------------|------|
| `id` | `String @id @default(uuid())` | `Column(String, primary_key=True, default=uuid4)` | 主键，自动生成 UUID |
| `proTopic` | `String` | `Column(String, nullable=False)` | 正方辩题 |
| `conTopic` | `String` | `Column(String, nullable=False)` | 反方辩题 |
| `background` | `String?` | `Column(String, nullable=True)` | 可选背景资料 |
| `debugMode` | `Boolean @default(false)` | `Column(Boolean, default=False)` | 是否调试模式 |
| `status` | `String @default("ongoing")` | `Column(String, default="ongoing")` | ongoing/completed |
| `judgePersonas` | `String?` | `Column(String, nullable=True)` | JSON 数组字符串，存被选中的裁判人格 ID |
| `result` | `DebateResult?` | `relationship("DebateResult", uselist=False)` | 一对一关联结果 |

### DebatePosition 模型

```prisma
model DebatePosition {
  id        String @id @default(uuid())
  debateId  String
  roleId    String // FK → Role.id
  side      String // "pro" | "con" | "judge"
  position  Int    // 1-4（judge 为 0）
  brainId   String // 冗余存储方便查询

  debate    Debate @relation(fields: [debateId], references: [id], onDelete: Cascade)

  @@index([roleId])
  @@index([debateId])
}
```

| 字段 | 说明 |
|------|------|
| `side` | 正方（pro）/ 反方（con）/ 裁判（judge） |
| `position` | 辩位 1-4，裁判为 0 |
| `brainId` | 冗余存储：不通过 role 查 brain 也能直接拿到 |

**`@@index([debateId])`** — 创建数据库索引，加快按 debateId 查询的速度。类似 Python SQLAlchemy 的 `Index('ix_debate_id', 'debate_id')`。

### DebateMessage 模型

```prisma
model DebateMessage {
  id          String   @id @default(uuid())
  debateId    String
  roleId      String   // 发言者 roleId
  side        String   // "pro" | "con" | "judge"
  position    Int      // 1-4（judge 为 0）
  round       String   // "opening" | "rebuttal" | "cross" | "free" | "closing" | "judging"
  content     String   // 发言内容
  tokenCount  Int?     // 该发言消耗的 token 数
  charCount   Int?     // 发言的实际字数（用于编排判定）
  roundIndex  Int      // 全场第几轮发言
  createdAt   DateTime @default(now())

  debate      Debate   @relation(fields: [debateId], references: [id], onDelete: Cascade)

  @@index([debateId, createdAt])
}
```

**`@@index([debateId, createdAt])`** — 联合索引：按 debateId + 创建时间排序查询时更快。

**重要字段**：`round` 记录所处的辩论阶段（opening/rebuttal/cross/free/closing/judging），而 `roundIndex` 记录全场第几轮发言（从 1 开始递增）。

### DebateScore 模型

```prisma
model DebateScore {
  id              String   @id @default(uuid())
  debateId        String
  roleId          String   // 辩手 roleId
  judgeRoleId     String?  // 评分裁判 roleId
  judgePersonaId  Int?     // 裁判人格编号 1-9
  side            String   // "pro" | "con"
  position        Int      // 1-4
  scoreContent    Int?     // 内容/论据 原始分 0-10
  scoreLogic      Int?     // 逻辑/推理 原始分 0-10
  scoreExpression Int?     // 表达/语言 原始分 0-10
  scoreRebuttal   Int?     // 反驳/应变 原始分 0-10
  totalScore      Float?   // 旧单裁判系统的加权总分（向后兼容）
  weightedTotal   Float?   // 程序按裁判人格权重计算的加权总分
  judgeComment    String?  // 裁判评语
  createdAt       DateTime @default(now())

  debate          Debate   @relation(fields: [debateId], references: [id], onDelete: Cascade)

  @@index([debateId])
  @@index([judgeRoleId])
}
```

**4 个评分维度**：`scoreContent`（内容论据）、`scoreLogic`（逻辑推理）、`scoreExpression`（表达语言）、`scoreRebuttal`（反驳应变）。每个维度 0-10 分。

**`weightedTotal`** — 程序计算的值。每个裁判有自己的人格权重（例如「严谨学者」最重视 logic），`weightedTotal` 按照该裁判的权重计算：

```
weightedTotal = content * w_content + logic * w_logic + expression * w_expression + rebuttal * w_rebuttal
```

### DebateResult 模型

```prisma
model DebateResult {
  id              String   @id @default(uuid())
  debateId        String   @unique
  winner          String   // "pro" | "con"
  bestPro         Int?     // 正方最佳辩手 position
  bestCon         Int?     // 反方最佳辩手 position
  overallBest     Int?     // 全场最佳辩手 position
  proTotalScore   Float?   // 正方总分
  conTotalScore   Float?   // 反方总分
  judgeIds        String?  // JSON 数组
  judgeSummary    String?  // 裁判总结
  createdAt       DateTime @default(now())

  debate          Debate   @relation(fields: [debateId], references: [id], onDelete: Cascade)
}
```

**`@unique`** — `debateId` 是唯一约束：一场辩论只有一个结果（一对一关系）。类似 SQLAlchemy 的 `UniqueConstraint`。

## 4. 辩论阶段定义与常量

文件：`main/handlers/debate.js`，第 1-60 行

### ROUNDS — 5 阶段定义

```javascript
const ROUNDS = [
  { phase: 'opening',  label: '立论',     budget: 700, maxTokens: 4096, speakerList: [{ side: 'pro', pos: 1 }, { side: 'con', pos: 1 }] },
  { phase: 'rebuttal', label: '驳论',    budget: 400, maxTokens: 4096, speakerList: [{ side: 'con', pos: 2 }, { side: 'pro', pos: 2 }] },
  { phase: 'cross',    label: '对辩',      budget: 300, maxTokens: null, speakers: 'cross', speakerPositions: [{ side: 'pro', pos: 3 }, { side: 'con', pos: 3 }] },
  { phase: 'free',     label: '自由辩论',   budget: 800, maxTokens: null, speakers: 'free' },
  { phase: 'closing',  label: '总结',     budget: 700, maxTokens: 4096, speakerList: [{ side: 'con', pos: 4 }, { side: 'pro', pos: 4 }] },
];
```

**`const ROUNDS = [...]`** — 一个数组包含 5 个对象，定义了整场辩论的全部阶段。

| 阶段 | label | budget(字) | maxTokens | 发言者 | 说明 |
|------|-------|-----------|-----------|--------|------|
| opening | 立论 | 700 | 4096 | 正1 → 反1 | 固定两人，各 700 字 |
| rebuttal | 驳论 | 400 | 4096 | 反2 → 正2 | 固定两人，各 400 字 |
| cross | 对辩 | 300 | null | 三辩交替 | 字数池共享，无需 max_tokens |
| free | 自由辩论 | 800 | null | 随机交替 | 字数池共享，无需 max_tokens |
| closing | 总结 | 700 | 4096 | 反4 → 正4 | 固定两人，各 700 字 |

**对比 Python**：

```python
# Python 里用列表或元组：
ROUNDS = [
    {"phase": "opening", "label": "立论", "budget": 700, "maxTokens": 4096, "speakerList": [{"side": "pro", "pos": 1}, {"side": "con", "pos": 1}]},
    ...
]
# JS 的花括号就是对象（= dict），方括号是数组（= list）
```

**`maxTokens: null`** — 对 cross 和 free 阶段，不限制 LLM 的 max_tokens（因为单次发言很短，LLM 自然会停止）。

**`speakerList` / `speakers` / `speakerPositions`** — 三种不同的发言者模式：
- `speakerList`：固定顺序的发言者列表
- `speakers: 'cross'`：对辩模式（双方三辩交替）
- `speakers: 'free'`：自由辩论模式（随机选派，但三辩有 50% 权重）

### POSITION_NAMES

```javascript
const POSITION_NAMES = ['', '一辩', '二辩', '三辩', '四辩'];
```

**为什么第一个是空字符串 `''`？** 因为 position 编号从 1 开始，所以 `POSITION_NAMES[0] = ''`（无意义），`POSITION_NAMES[1] = '一辩'`。这是为了直接通过 position 数值索引——`POSITION_NAMES[pos]` 就是对应的中文名。

对比 Python：

```python
# Python 可以用 dict：
POSITION_NAMES = {1: '一辩', 2: '二辩', 3: '三辩', 4: '四辩'}
# 或者带占位符的列表：
POSITION_NAMES = ['', '一辩', '二辩', '三辩', '四辩']
```

### PHASE_PROMPTS — 每个阶段的中文指令

```javascript
const PHASE_PROMPTS = {
  opening: {
    pro: '现在是你方立论环节。作为正方开篇，为本场辩论定下基调。篇幅建议 600~700 字之间。',
    con: '现在是你方立论环节。作为反方开篇，建立本方论证框架。篇幅建议 600~700 字之间。',
  },
  rebuttal: {
    con: '现在是驳论环节，你的任务是反驳正方立论、加固本方立场。篇幅建议 300~400 字之间。',
    pro: '现在是驳论环节，你的任务是反驳反方立论、修复和巩固本方立场。篇幅建议 300~400 字之间。',
  },
  cross: '现在进入对辩环节，你和对方三辩多轮交替发言。留意上方的字数配额——你方还剩多少、对方还剩多少，都是重要信息。建议单次控制在 30~80 字以内，一句有力的质问或回应往往比长篇大论更有效，但不强制。\n如果你方字数用完，本轮失去发言权；如果对方字数先用完，你方依然可以继续输出直到自己也耗尽——可以一次打完所有剩余字数，也可以继续保持多轮短促输出。',
  free: '现在是自由辩论环节，双方交替发言，节奏紧凑。每次随机选派一名辩手出场，现在轮到你。\n\n留意上方的字数配额——你方还剩多少、对方还剩多少，都是重要信息。建议单次控制在 30~80 字以内，一句有力的质问或回应往往比长篇大论更有效，但不强制。\n如果你方字数用完，本轮失去发言权；如果对方字数先用完，你方依然可以继续输出直到自己也耗尽——可以一次打完所有剩余字数，也可以继续保持多轮短促输出。',
  closing: {
    con: '现在是总结陈词环节，你是反方收尾。回顾全场，指出正方始终未能解决的问题，升华本方立场。篇幅建议 600~700 字之间。',
    pro: '现在是总结陈词环节，你是正方收尾。回顾全场，指出反方始终未能有效回击的核心论点，升华本方立场。篇幅建议 600~700 字之间。',
  },
};
```

**类型混合**：`opening`、`rebuttal`、`closing` 的值是对象（有 `pro` 和 `con` 两个属性），`cross` 和 `free` 的值是字符串。因为在 `buildSystemPrompt` 函数中会这样处理：

### pickFreeDebater — 三辩加权随机

```javascript
function pickFreeDebater(positions) {
  const third = positions.find(p => p.position === 3);
  if (third && Math.random() < 0.5) return third;
  const others = positions.filter(p => p.position !== 3);
  return others[Math.floor(Math.random() * others.length)];
}
```

**`Math.random()`** — 返回 [0, 1) 间的随机浮点数。Python 是 `random.random()`。

**`Math.floor(Math.random() * others.length)`** — 生成 0 到 `others.length-1` 的随机整数。Python 是 `random.randint(0, len(others)-1)` 或 `random.randrange(len(others))`。

三辩被选中的概率不是均匀的：
- 50% 概率直接选中三辩（不管本方有几位辩手）
- 50% 概率从所有非三辩中随机选

如果本方只有三辩一人（其他位置没配置），则 50% 概率返回三辩，50% 概率返回 `undefined`（会触发报错）。

### pickN — 随机选择 N 个元素

```javascript
function pickN(n, arr) {
  const shuffled = [...arr].sort(() => Math.random() - 0.5);
  return shuffled.slice(0, n);
}
```

**`[...arr]`** — 用 spread 操作符浅拷贝数组，防止修改原数组。相当于 Python 的 `arr[:]`。

**`.sort(() => Math.random() - 0.5)`** — 黑科技随机洗牌。`sort` 接受一个比较函数，返回负数表示 a 在前，正数表示 b 在前。`Math.random() - 0.5` 约 50% 概率为负数、50% 为正数，所以排序结果近似随机。

⚠️ **这不是真正的随机洗牌**：`sort` 的稳定性 + 伪随机可能导致不均匀分布。如果要求严格的均匀分布，应该用 Fisher-Yates 算法。但对于选 3 个裁判人格这种场景，这个简单的实现足够了。

### streamSpeech — SSE 流式 LLM 调用

```javascript
async function streamSpeech(brain, messages, maxTokens, onDelta, onDone) {
  const body = {
    model: brain.modelName,
    messages,
    stream: true,
  };
  if (maxTokens) body.max_tokens = maxTokens;

  const response = await fetch(`${brain.baseUrl}/chat/completions`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${brain.apiKey}`,
    },
    body: JSON.stringify(body),
  });
```

**`streamSpeech`** 接受 5 个参数：
1. `brain` — 大脑配置（含 baseUrl, apiKey, modelName）
2. `messages` — LLM 消息数组
3. `maxTokens` — 最大 token 数（null 表示不限制）
4. `onDelta(token)` — 每次收到新的 token 时调用的回调
5. `onDone(fullText, totalTokens)` — 流结束时调用的回调

这种设计使 `streamSpeech` 可以复用：辩论中用它生成辩手发言，裁判评分时也用它（但裁判评分时不关心 delta，只传空函数给 `onDelta`）。

---

```javascript
  if (!response.ok) {
    const err = await response.text();
    throw new Error(`API error ${response.status}: ${err}`);
  }

  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buf = '';
  let full = '';
  let totalTokens = 0;

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buf += decoder.decode(value, { stream: true });
    const lines = buf.split('\n');
    buf = lines.pop() || '';

    for (const line of lines) {
      const trimmed = line.trim();
      if (!trimmed.startsWith('data: ')) continue;
      const data = trimmed.slice(6);
      if (data === '[DONE]') continue;

      try {
        const json = JSON.parse(data);
        const delta = json.choices?.[0]?.delta?.content || '';
        if (delta) {
          full += delta;
          onDelta(delta);
        }
        if (json.usage?.completion_tokens) {
          totalTokens = json.usage.completion_tokens;
        }
      } catch { /* skip malformed */ }
    }
  }
```

**SSE 分片积累技巧**：

```javascript
buf += decoder.decode(value, { stream: true });
const lines = buf.split('\n');
buf = lines.pop() || '';
```

`split('\n')` 将缓冲区按换行分割。最后一行可能不完整（下一个分片才到），所以 `lines.pop()` 把它存回 `buf` 等待下次拼接。完整行则遍历处理。

这解决了 **TCP 分片切断了 SSE 行** 的问题。例如：

```
第 1 次收到：'data: {"choices":[{"delta":{"content":"你好"\n'
第 2 次收到：'n}]}}\n'
```

处理流程：
- 第 1 次：`buf=''` → `lines=['data: {"choices":[{"delta":{"content":"你好"', '']` → `buf='\n'`（不完整行）
- 第 2 次：`buf='\n'` → `buf + 'n}]}}\n'` → `lines=['', 'n}]}}\n']` → 第一行为空，跳过；处理的是不完整的 JSON，`catch` 忽略；第二行 `n}]}}\n` 也不是有效行
- 这在实际使用中没问题，因为 SSE 的每行 JSON 通常不会跨分片

### buildUserMessage — 构建用户消息

function buildUserMessage(allMsgs, roundPhase, mySide, myUsed, myBudget, oppUsed, oppBudget, roundIdx) {
  const roundDef = ROUNDS.find(r => r.phase === roundPhase);
  const label = roundDef ? roundDef.label : roundPhase;

  let msg = `以下是截至目前本场辩论的全部记录：\n---\n`;
  if (allMsgs.length === 0) {
    msg += '（暂无历史记录，你是第一个发言）\n';
  } else {
    for (const m of allMsgs) {
      const s = m.side === 'pro' ? '正方' : m.side === 'con' ? '反方' : '裁判';
      const pos = m.position > 0 ? POSITION_NAMES[m.position] : '';
      msg += `[${s}${pos}]：${m.content}\n`;
    }
  }
  msg += `---\n\n`;
  msg += `当前环节：${label}\n`;
  msg += `这是整场辩论的第 ${roundIdx} 轮发言。\n`;

  if (roundPhase === 'cross' || roundPhase === 'free') {
    const myRem = Math.max(0, myBudget - myUsed);
    msg += `我方已使用 ${myUsed} 字（共 ${myBudget}），对方已使用 ${oppUsed} 字（共 ${oppBudget}）\n`;
    msg += `（我方剩余 ${myRem} 字，累计达到 ${myBudget} 字后我方失去发言权）\n`;
  } else if (roundDef) {
    const lo = Math.round(roundDef.budget * 0.85);
    msg += `本环节建议输出约 ${lo}~${roundDef.budget} 字的内容。\n`;
  }

  msg += `\n轮到你发言了：`;
  return msg;
}
```

**`ROUNDS.find(r => r.phase === roundPhase)`** — 从 ROUNDS 数组中找 phase 匹配的轮次定义。`.find()` 返回第一个匹配元素，类似 Python 的 `next((r for r in ROUNDS if r['phase'] == round_phase), None)`。

**`Math.max(0, myBudget - myUsed)`** — 确保剩余字数不小于 0。Python 里是 `max(0, my_budget - my_used)`。

### 对辩/自由辩论字数机制

对辩和自由辩论阶段的核心策略：

1. **字数池共享** — 每方有一个总预算（cross: 300 字，free: 800 字），全队共享
2. **用完即止** — 字数用完后该方失去发言权
3. **对方先用完** — 你方可以继续输出，直到也用完预算

```

### aggregateJudging — 聚合评分与判定胜负

```javascript
async function aggregateJudging(state) {
  const scores = await prisma.debateScore.findMany({
    where: { debateId: state.debateId, weightedTotal: { not: null } },
  });

  // Group by roleId, collect weightedTotals from all judges
  const byRole = {};
  for (const sc of scores) {
    if (!byRole[sc.roleId]) {
      byRole[sc.roleId] = { side: sc.side, position: sc.position, roleId: sc.roleId, totals: [] };
    }
    if (sc.weightedTotal != null) byRole[sc.roleId].totals.push(sc.weightedTotal);
  }

  // Average per debater
  const avgs = Object.values(byRole).map(d => ({
    ...d,
    average: d.totals.length > 0 ? d.totals.reduce((a, b) => a + b, 0) / d.totals.length : 0,
  }));

  // Team totals
  const proSum = avgs.filter(d => d.side === 'pro').reduce((s, d) => s + d.average, 0);
  const conSum = avgs.filter(d => d.side === 'con').reduce((s, d) => s + d.average, 0);
  const winner = proSum >= conSum ? 'pro' : 'con';
```

**聚合逻辑**：

```
每个辩手有 3 个评分（来自 3 位裁判）→ 取平均 → 得到每人的平均分
正方 4 人平均分之和   → proSum
反方 4 人平均分之和   → conSum
proSum >= conSum → 正方胜，否则反方胜
```

**`Object.values(byRole)`** — 返回对象所有值的数组。类似 Python 的 `by_role.values()`。

**`sc.weightedTotal != null`** — `!=` 而不是 `!==`，这样会同时排除 `null` 和 `undefined`（但不排除 0）。在 JS 中 `null != undefined` 为 false，所以两者都会被排除。

---

```javascript
  // Best debaters
  const allBest = avgs.reduce((best, d) => (!best || d.average > best.average) ? d : best, null);
  const proBest = avgs.filter(d => d.side === 'pro').reduce((best, d) => (!best || d.average > best.average) ? d : best, null);
  const conBest = avgs.filter(d => d.side === 'con').reduce((best, d) => (!best || d.average > best.average) ? d : best, null);

  // Write results
  await prisma.debateResult.create({ ... });
  await prisma.debate.update({
    where: { id: state.debateId },
    data: { status: 'completed' },
  });

  active.delete(state.debateId);
  state.completed = true;

  return { winner, bestPro: proBest?.position, bestCon: conBest?.position, overallBest: allBest?.position, proTotal: proSum, conTotal: conSum };
}
```

**`arr.reduce((best, d) => (!best || d.average > best.average) ? d : best, null)`** — 用 reduce 实现"找最大值"：

```javascript

// 或者更简单：

```

**`proBest?.position`** — 可选链访问。如果 `proBest` 是 null/undefined，返回 undefined 而不是抛 TypeError。Python 没有这个语法。

```typescript
export interface DebateCallbacks {
  onDelta?: (data: { ... }) => void;
  onPrompt?: (data: { system: string; user: string }) => void;
  onRoundDone?: (data: { ... }) => void;
  onJudgingDone?: (data: { personaCount: number }) => void;
  onDone?: (data: { winner: string; scores: any[]; summary: string }) => void;
  onError?: (data: { error: string }) => void;
}

export function subscribeDebate(callbacks: DebateCallbacks): () => void {
  if (!isElectron) {
    callbacks.onError?.({ error: 'No Electron context' });
    return () => {};
  }

  const cleanups: (() => void)[] = [];
  if (callbacks.onDelta) cleanups.push(api!.debate.onDelta(callbacks.onDelta));
  if (callbacks.onPrompt) cleanups.push(api!.debate.onPrompt(callbacks.onPrompt));
  // ...

  return () => cleanups.forEach((fn) => fn());
}
```

**`callbacks.onError?.({ error: 'No Electron context' })`** — 可选链调用 `?.()`。如果 `onError` 是 undefined，不会报错，直接跳过。

**`api!.debate.onDelta(callbacks.onDelta)`** — `!` 是 TS 的非空断言，告诉 TypeScript "我确定 api 不为 null"。因为前面已经用 `if (!isElectron) return` 判断过了。

  const phaseOrder = ['opening', 'rebuttal', 'cross', 'free', 'closing'];
  let phaseIndex = 0;
  let phaseStepIndex = 0;
  let perSideChars = { pro: 0, con: 0 };

  for (let i = 0; i < phaseOrder.length; i++) {
    const phase = phaseOrder[i];
    const roundDef = ROUNDS[i];
    const phaseMsgs = debate.messages.filter(m => m.round === phase);
    const phaseChars = { pro: 0, con: 0 };
    for (const m of phaseMsgs) {
      const c = m.charCount || m.content.length || 0;
      if (m.side === 'pro') phaseChars.pro += c;
      if (m.side === 'con') phaseChars.con += c;
    }

    let phaseComplete = false;
    if (roundDef.speakerList) {
      phaseComplete = roundDef.speakerList.every(sp =>
        phaseMsgs.some(m => m.side === sp.side && m.position === sp.pos)
      );
    } else if (roundDef.speakers === 'cross') {
      phaseComplete = phaseChars.pro >= roundDef.budget && phaseChars.con >= roundDef.budget;
    } else if (roundDef.speakers === 'free') {
      phaseComplete = phaseChars.pro >= roundDef.budget && phaseChars.con >= roundDef.budget;
    }

    if (!phaseComplete) {
      phaseIndex = i;
      perSideChars = phaseChars;
      break;
    }
  }

**恢复状态的核心逻辑**：

1. 从头遍历 5 个阶段
2. 对每个阶段，从已有消息中筛选出属于该阶段的消息
3. 计算该阶段双方已用字数
4. 判断该阶段是否完成：
   - 固定发言者：检查 `speakerList` 中的每个人是否都已发言
   - 对辩/自由辩论：检查双方字数是否都用完
5. 如果阶段未完成，设置 `phaseIndex` 为该阶段，保留字数信息，跳出循环

**`arr.every(fn)`** — 测试数组是否**所有**元素都满足条件。类似 Python 的 `all(fn(x) for x in arr)`。

**`arr.some(fn)`** — 测试是否**至少有一个**元素满足条件。类似 Python 的 `any(fn(x) for x in arr)`。

### 关键设计决策

| 决策 | 原因 |
|------|------|
| 步进式执行（每次 1 轮）而不是一次跑完 | 用户体验：用户能看到每轮发言，控制节奏 |
| State 存在内存 Map 而非全放数据库 | 状态机需要频繁读写，内存比 SQLite 快几个数量级 |
| 3 个裁判并行而非串行 | LLM 调用是主要耗时，并行节省 2/3 时间 |
| 裁判评分用同一个 brain（不同 prompt） | 不需要额外配置，也方便对比不同人格的输出 |
| 字数预算代替 token 预算 | 中文场景下字数是更直观的约束 |
| 自由辩论三辩 50% 权重 | 提高三辩出场率，模拟真实辩论中三辩的角色更重要 |
| 模拟流式输出裁判评分 | 复用前端的流式渲染逻辑，统一用户体验 |
